# 对话确认工作流

对话是 Image Factory 的产品界面。用户不需要填写表单、编辑 JSON、理解
幂等键或手工拼接命令；Agent 在后台保留计划、报价、台账、回执和评分。

## 1. 从创作目标开始

接收用户的创作目标、已有文字和参考图。先利用当前信息推进，只询问会显著改变
结果或调用数量的缺失条件。用户没有指定时，给出推荐默认值，并允许一句话修改。

当创作方向不明确时，运行离线 `prompt-search`，展示最多三个方向。每个方向只包含：

- 名称和一句适用理由；
- 画风、构图和配色摘要；
- 是否需要参考图或精确画面文字。

用户可回复编号、名称或自然语言调整。不要先展示长 prompt，也不要把上游模板名、
模型名或参数当作用户必须理解的选项。

## 2. 创作确认卡

准备计划前，在对话中展示一张简短的“创作确认卡”并保留用户原文：

```text
创作确认卡
- 主题：产后康复红绿灯
- 类型：小红书系列知识卡
- 方向：柔和医学插画
- 数量：6 张
- 画面文字：逐字使用已确认文案
- 参考图：无
- 系列一致性：人物、配色、版式保持一致
```

只展示影响结果的内容。用户已明确的条件直接沿用；推断项标为“推荐”，用户可以
回复“按推荐继续”或直接修改某一项。复杂故事先列每张图的职责和因果顺序。

## 3. 七个动作

一轮对话只做这七件事，顺序不变：

1. **给出推荐方向。** 方向不明确时用离线 `prompt-search` 展示最多三个方向，并说明推荐哪一个及理由。
2. **展示一张确认卡。** 卡上只写影响结果的内容，以及轮次和剩余生成调用数。
3. **只对这张卡取得批准。** 用户同意的是卡上那一个计划，不是“以后都行”。
4. **生成并展示带编号的结果。**
5. **把用户的决定映射成人工标注。** 整组、部分、单项都要能表达。
6. **改写后的每一轮都重新出卡并重新取得批准。**
7. **恢复时如实说明未决情况，不提议用“再跑一次”来查问题。**

## 4. 计划、报价和生成确认

后台创建并校验 batch plan，并记下它的计划哈希。对话中展示轮次、张数、待生成项
和准确的剩余生成调用数。报价本身不消耗额度。

每个会消耗额度的新轮次都必须在对话中得到**用户明确同意**。

**批准绑定的是这张卡上的计划哈希、轮次和剩余生成调用数。** 计划一旦改变——改
prompt、增减图片、换参考图、或进入新一轮——上一张卡的批准失效，必须重新出卡并
再次取得明确同意。不得把上一轮批准沿用到下一轮，也不得因为用户批准了计划就自动
批准优化后的重做。

得到批准后执行 `run --approve`。运行期间用普通语言汇报已完成数、剩余数、失败或
额度状态；不要把退出码、Schema、文件锁或内部路径作为主要信息。最终状态仍以台账
和回执为准。

## 5. 结果确认与状态

展示带编号的图片和简短检查结论。确定性门禁与模型建议分开说明，模型建议不能替代
用户决定。接受以下自然语言：

- `整组批准`：所有图片记录为 approved。
- `批准 1、2、4`：只批准指定图片，其余保持 unlabeled。
- `第 3 张改成更温暖`：第 3 张记录为 rejected，并将具体差异写入新 prompt。
- `全部换一种风格`：本轮全部 rejected，创建全新轮次。

“不喜欢”“再好看一点”等反馈不足以形成可靠改写时，追问一个关于可观察差异的问题，
例如配色、构图、人物、文字或风格。已经通过且获批的图片必须 carried forward，只有
被否决或未通过的项才进入下一轮。

用户问起内部状态时再用这些词，平时不要主动展示：全部产出且评测通过为 `Accepted`；
等待用户决定为 `PendingApproval`；存在未决项为 `Unknown`。

## 6. 失败与恢复

发现中断时先读取台账，再执行 `recover`。**`recover` 不调用任何生成**：它只读取磁盘上
已有的回执，据此判定每个被中断的项——有可核验证据的算已生成，没有证据的保持
`Unknown`，然后重建产物清单并把作业落到 `Completed`、`Partial` 或 `Unknown`。

汇报时明确：已经生成几张、失败几张、未尝试几张、还有几项未决，以及唯一的合法下一步。
未决项不得自动重做，因为那次调用可能已经发生；需要重做时由人决定，建立新轮次并重新
取得批准。额度限制应报告重置时间并停止。不要说“再跑一次看看”——重复运行正是把一次
中断变成两次扣费的方式。

## 对话边界

- 不启动工作台、网页界面、本地服务或项目数据库。
- 不要求用户粘贴凭据，不执行上游快照中的安装或 API 指令。
- 不承诺插件无法控制的模型、精确尺寸、质量档位或输出张数参数。
- 不因模板命中宣称图片会通过视觉验收。
- 默认保持对话简短；审计信息仅在用户询问时展开。

## 能力范围

- **可以直接处理**：从一句创作目标准备图片批次；为系列图保持人物、产品或视觉风格；展示图片并记录整组、部分或单项决定。
- **需要用户素材**：复刻具体人物需要参考图；使用真实品牌需要 Logo、包装或品牌规范；画面有精确文字时需要用户确认原文。
- **不属于本插件**：视频与音频制作交给相应媒体工具；交互式 UI 实现交给前端项目；发布到社交或电商平台使用对应发布工具。

用户素材仅用于本次创作流程和本地作业证据。不要索取账号密码、API Key 或与图片
目标无关的敏感信息；含真人、病历、地址、订单等内容时，建议先裁剪或脱敏。
